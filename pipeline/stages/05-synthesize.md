## 这是整条流程的智力核心

前四个阶段是"收集"，本阶段是"判断"。官方列出的通讯评审负面意见中，第 1、2、3 条都指向本阶段的产出质量：

> （1）对本领域已有研究现状了解不清楚或不全面，拟研究的科学问题或所设计的研究内容有较多简单重复前人工作；
> （2）拟选择研究的创新性科学问题不明确，未提炼出明确的关键科学问题；
> （3）对拟开展的研究工作缺乏清晰连贯的科学构思或工作模型，逻辑不清，未准确地定位和分析拟解决的关键科学问题。

## 步骤

### 1. 划分研究主线

从 `notes/_index.md` 出发，把文献归入 **3-4 条研究主线**。

- 按**方法论脉络**划分，不是按时间线，也不是逐篇罗列
- 每条主线应有清晰的演进方向（从简单到复杂、从单一到系统）
- 主线数量 3-4 条；过多会稀释判断力

每条主线写明：定位、演进脉络、代表性工作、**能力边界**（目前能做什么、在什么条件下失效）。

### 2. 提炼结构性不足（本阶段最重要）

**什么是结构性不足**：现有方法所依赖的**假设**或**设计范式**，在某类条件下必然失效，且**无法通过在同一范式内修补来解决**。

| | 表述 | 为什么 |
|---|---|---|
| ❌ | 现有方法准确率不足，仍有提升空间 | 指标层面，评审读成"想刷点" |
| ❌ | 已有工作尚未在某数据集上验证 | 补个实验就能做，不必立项 |
| ❌ | 相关研究较少 | 研究少 ≠ 重要 |
| ✅ | 现有方法普遍假设 A 成立（见 <ref>），而在 B 场景下 A 必然不成立，导致整类方法失效 | 假设层面、条件明确 |
| ✅ | 该问题目前只能给出经验性判据，尚缺乏关于 C 的理论刻画 | 明确指出认识空白 |

**每条不足必须写成三段式**：

```markdown
**不足 N：<一句话表述>**
- **已有工作的假设/设计**：<具体引用文献，说明它依赖什么>
- **该假设/设计何时失效**：<具体条件，不是"某些情况下">
- **因此未被覆盖的问题**：<由此推出的、尚未被回答的问题>
```

**证据要求**：每条不足至少关联 **2 篇**文献（单篇易被质疑是个别缺陷而非领域性问题）。

### 3. 凝练候选科学问题（1-2 个）

**数量为 1-2 个。** 官方评审指导明确要求关键科学问题"一定要集中到 1~2 个点上"，并指出"内容过多，一个项目很难完成"是常见问题。

**每个科学问题必须写成可证伪形式**：

```
在 [限定条件] 下，[某现象] 是否源于 [某机理]？
若成立，则 [可观测的推论]。
```

三个要素缺一不可：
- **限定条件**：范围与假设，体现问题边界
- **机理猜想**：关于"为什么"，不是"是什么"
- **可观测推论**：假说成立时应观察到什么（可证伪性的保障）

**并且必须写出否定条件**：

```
否定条件：若观察到 [具体结果]，则该假说被推翻。
```

**若写不出否定条件，说明它还不是科学问题。**

**形态自检**（官方口径："科学问题是 science，不是 technology"）：

| 形态 | 判定 |
|---|---|
| "如何在不依赖 A、B、C 的条件下实现 X" | ❌ 技术目标 |
| "如何把指标提升到 Z" | ❌ 指标目标 |
| "X 现象是否源于 Y 机理" | ✅ |
| "在约束 W 下，某类方法是否存在可证明的界限" | ✅ |
| "是否存在某结构使原问题可解" | ✅ |

### 4. 撰写调研报告 `deliverables/调研报告.md`

面向人阅读的完整报告，结构：

```markdown
# <主题> 调研报告
## 摘要（300 字以内：领域现状、最主要的结构性不足、建议方向）
## 一、研究背景与范围
## 二、检索方法（数据源、检索式数量、纳入/排除标准、最终纳入 N 篇）
      —— 必须如实报告检索的局限性
## 三、研究主线梳理（3-4 条）
## 四、结构性不足（三段式，附证据编号）
## 五、候选科学问题（可证伪形式，含否定条件）
## 六、研究机会与建议
## 七、证据索引
## 八、附录（全部纳入文献、检索式清单、未解决的检索式）
```

参考文献生成：

```bash
node bin/cli.mjs format --lib runs/<项目名>/work/library.json --style gbt7714 --out runs/<项目名>/deliverables/refs-调研报告.md
```

### 5. 撰写交接物 `work/GAP-MAP.md`

结构固定（见 `pipeline/templates/GAP-MAP.template.md`）：

```markdown
## 1. 研究属性
## 2. 研究主线划分
## 3. 结构性不足（三段式）
## 4. 候选科学问题（含限定条件/机理猜想/可观测推论/否定条件）
## 5. 证据索引
## 6. 检索覆盖度自评（含如实报告的局限）
## 7. 待用户确认事项
```

## 完成判据

### 硬判据

- **H1**：`work/GAP-MAP.md` 存在，7 个小节齐全
- **H2**：结构性不足 ≥ 3 条，且**每条都写成三段式**
- **H3**：**每条不足至少 2 篇文献支撑**
- **H4**：候选科学问题 1-2 个，**每个都含限定条件、机理猜想、可观测推论、否定条件**四项
- **H5**：科学问题形态通过自检（非技术目标、非指标目标）
- **H6**：`deliverables/调研报告.md` 存在，含检索局限性说明
- **H7**：不存在"指标不足"式伪不足（逐条检查：若一条不足可通过"再调调参/换个数据集"解决，即为伪不足）

### 软判据

- **S1**：研究主线 3-4 条，每条有清晰演进脉络
- **S2**：调研报告摘要 ≤300 字且点明最主要不足
- **S3**：检索覆盖度自评如实（未夸大覆盖）
- **S4**：候选科学问题与不足编号可追溯
- **S5**：待用户确认事项已列出

### 评级

对照官方综合评价等级定义自评（见 `docs/官方评判据.md`）。
额外考虑一条：**候选科学问题是否具备"此前未被回答"的性质**——若答案是"其实已经有人做过类似的"，最高只能给"中"。

## 陷阱

| 陷阱 | 识别方法 |
|---|---|
| **把"研究少"当不足** | 问：研究少是因为不重要，还是因为难？必须是后者 |
| **不足只有 1 篇证据** | 可能是该篇的个别缺陷，不是领域性问题 |
| **科学问题写成技术目标** | 无法写出否定条件 |
| **科学问题数量过多** | 超过 2 个即需削减 |
| **机理猜想空泛** | 把研究对象替换成别的项目仍成立，即为空泛 |
| **夸大检索覆盖** | 检索局限性必须如实写入报告 |
