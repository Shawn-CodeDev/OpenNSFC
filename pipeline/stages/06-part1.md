## 执行要点

### 要点 1：论证链必须五拍齐全（放在「1.研究背景与意义」下）

```
第一拍  领域当前的能力水平与代价        ← 要有具体数字或明确范围
第二拍  瓶颈：现有方法在什么条件下失效    ← 具体条件、具体失效模式
第三拍  根因：为什么修补解决不了         ← 全篇支点，取自 GAP-MAP 第 3 节
第四拍  申请人的前期发现                ← 枢纽：把根因变成一个可下手的方向
第五拍  科学问题 + 可证伪科学假说        ← 取自 GAP-MAP 第 4 节
```

**第三拍不得弱化**。若立项依据读起来是"领域很热 → 所以我要做"，说明第三拍缺失。

**第四拍是整份本子的枢纽，最容易被漏掉。** 第三拍只说清了"别人为什么不行"，
第四拍才回答"那凭什么你能行"——必须写成一个**申请人自己观察到的、具体的经验事实或
初步发现**，而不是一句"本项目拟研究 X"。

参考获批本的原话结构（事件相机方向）：

> 究其原因，现有的事件相机目标检测算法大多……对事件数据的先验信息和成像特性利用较少。
> **申请人通过前期的研究发现**事件相机成像中目标事件具有显著的几何结构，如柱状、线状结构。
> 而背景事件大多为面状结构，且运动方向与目标事件有显著差异。
> **基于此**，本课题通过对几何结构进行显式建模……

注意它的推进方式：**根因（先验利用少）→ 前期发现（目标柱状/背景面状）→ 对策（显式几何建模）**。
前期发现本身是一个**可被独立验证的观测**，不是研究计划。三条判据：

| 判据 | 说明 |
|---|---|
| **具体** | 有明确对象与属性（"目标事件呈柱状、背景呈面状"），不是"存在一定规律" |
| **可独立验证** | 能用已有数据/一次小实验确认，不需要本项目做完才知道 |
| **直接指向对策** | 从这条观察能自然推出研究方案的核心机制 |

若申请人无法提供真实的初步发现，**不得编造**——此时改为写"尚未建立"
并在（三）研究基础中说明拟如何先行验证；宁缺勿造。

建议用 6 个四级小标题承载五拍：
- 趋势与代价（第一拍）
- 现有方法在何处失效（第二拍）
- 理论侧刻画的局限 / 根因（第三拍）
- 前期研究发现（第四拍）
- 两个并存事实的矛盾（问题必要性）
- 本项目拟回答的科学问题（第五拍，含否定条件）

### 要点 2：执行「替换检验」剔除话术

官方要求"摒弃各种'套路'和'话术'"。逐句检查：

> 把句中的研究对象替换成另一个项目，句子是否仍然成立？**成立 → 该句是话术，删除或改写。**

典型话术（禁止使用）：
- "X 已成为 Y 的重要基础/关键能力"
- "不再是 A，而是 B"
- "有助于深化对 X 本质的认识"（作小标题）
- "为……提供了新的切入点"（除非紧跟具体说明切入点是什么）
- "具有重要的理论意义和现实意义"

**实测标尺（重要）**：一份**已获批**的青年本全文，以下词的出现次数全部为 **0**——
「首次」「国际领先」「填补空白」「国内外首创」「率先」「突破性」「有望」「可望」
「旨在」「亟需」「亟待」；「国家战略」只在开头占 16 字，「具有重要意义」仅 1 次。

> **推论**：不用这些词完全能中。它们的实际作用是**替代具体论证**——用了反而暴露
> 论证链有缺口。把"具有重要意义"改成"现有方法在 X 条件下失效，因为没有利用 Y"，
> 信息量立刻不同。

**但注意一个例外**：陈述**被引文献的贡献**时用"首次"是正常的
（如"TRACE 识别物体边界**首次**出现的时刻［5］"）。
禁止的是**自我宣称式**的"首次/率先"。`check-consistency.mjs` 会按此区分做提示。

### 要点 2b：引用纪律——陈述他人必引，**缺口句一句都不引**

这是实测出来的、最容易忽略的一条规律。获批本 29 条文献、内文 30 处引用，
分布呈现**严格的二分**：

| 句子类型 | 是否带引用 | 原因 |
|---|---|---|
| 陈述他人成果/数据（"Perot 等人［27］……"、"RVT［29］……"） | **必须带** | 不带就是编造 |
| **指出缺口/局限的句子** | **一句都不带** | 缺口是**申请人自己的判断**，借他人权威反而削弱"这是我发现的"这一主张 |

因此缺口句的合法性**完全由"申请人前期的研究发现"承担**（见要点 1 第四拍）。
这也解释了为什么第四拍要求那么严：**它替掉了引用，所以必须比引用更硬。**

写作时逐句核查：

- [ ] 凡陈述他人具体成果、指标、结论的句子 → 逐句回查引用编号
- [ ] 凡缺口句 → 确认它靠的是自己的论证，而非"某某指出……"
- [ ] 内文引用总数与文献列表条数**不宜悬殊**。获批本 29 条 / 30 处 ≈ 一篇一次；
      若你的内文引用数远大于文献条数（同一篇被反复引用十几次），说明在拿同一篇
      文献反复充当背景，应补检索

```bash
# 双向校验：missingInList（正文引了列表没有）为阻断，unusedInText（列表有正文没引）应为空
node bin/cli.mjs validate --manuscript <正文.md> --lib <library.json> --strict
```

### 要点 3：按研究属性分流

| 属性 | 写法 |
|---|---|
| **自由探索类** | 不论证应用需求；聚焦科学问题本身的原创性；**必须有前期预实验或理论结果支撑**；可省略应用前景论证 |
| **目标导向类** | 论证链多一环：需求真实性 → 为什么这是科学问题而非工程任务 → 科学问题；需求必须有据可查 |

**自由探索类若被要求写应用前景**：明确说明理由（官方定义：不以满足现阶段应用需求为目的），不强行论证。

### 要点 4：「2.国内外研究现状」必须显式分类，不许流水账

**先立分类轴，再逐类评述。** 获批本的做法是开篇一句话给出分类轴与类别数，之后严格按该
分类展开——读者一眼就知道这条主线的全貌，也才知道"缺口"是在哪个坐标上出现的。

参考获批本原文：

> 根据数据格式可将事件数据的表征方式分为**七类**：基于图像的表征、基于表面的表征、
> 基于体素的表征、基于图的表征、基于脉冲的表征、基于点云的表征和基于学习的表征。

**分类轴必须从本项目的问题出发选取**，常见可选轴：

| 分类轴 | 适用情形 | 例子 |
|---|---|---|
| 按**数据表征形式** | 问题出在"输入范式不合适" | 图像/表面/体素/图/脉冲/点云 |
| 按**方法流派** | 问题出在"某类方法有共同假设" | 知识驱动 / 数据驱动 / 二者联合 |
| 按**建模对象层次** | 问题出在"建模粒度不对" | 像素级 / 区域级 / 结构级 |
| 按**任务设定** | 问题出在"设定与现实不符" | 静止平台 / 动平台；单模态 / 多模态 |

**逐类评述时统一用「能做什么 → 局限在哪」两段式**，且**局限要与同一套判据对齐**——
这样所有类别的短板才能在末尾自然合并成同一个结构性缺口。获批本的逐类局限：

> 基于体素的表征……由于多个事件合并，这类方式**舍弃了事件数据高时间分辨率的特性**……
> 基于图的表征……**由于噪声的影响，节点之间的关系并不稳定**。
> 基于脉冲的表征……**由于 SNN 难以训练且缺乏适配脉冲神经网络的专业硬件**，限制了该领域的发展。

**每条主线必须以下面四步收口**（这是获批本最值得学的一段结构）：

```
① 归纳共性局限   → "上述表征方式或……或……，但……难以兼顾异步性、时空异质性和双极性"
② 指出被忽略的点 → "大多将两者简单覆盖……忽略了两者的伴随特性"
③ 申请人的前期发现 → "申请人前期的研究发现，事件的极性关系可以相互转化"
④ 本课题的应对    → "本课题以几何感知为出发点……研究基于时空关联的双极性事件点云表征"
```

第 ③ 步与要点 1 的第四拍是同一个东西的两次出现：**在背景处首次提出，在研究现状处
再次落地**。这条闭环是"缺口 → 研究内容"映射的显式证据。

其他硬性要求：

- 3-4 条主线，每条 200-400 字；**主线数量与分类轴给出的类别数一致**，不自相矛盾
- 每条主线末尾的不足必须是**结构性不足**（假设层面、范式层面），不是"精度不够""速度慢"
- 不足必须与 GAP-MAP 第 3 节一致
- **覆盖国内代表性工作**，不得刻意压低国内文献
- 综述类文献（尤其是中文综述）适合作为分类轴的立论依据，可放在主线开篇

### 要点 4b：引用密度宜"少而准"，别堆砌

获批本正文 29 条参考文献、内文引用标记 30 处——**基本一篇引一次**，且每处都落在
"某类方法的代表工作"或"某条局限的证据"上，没有为了凑数而罗列。

反过来说：**内文引用数 >> 文献列表条数**（同一篇被反复引用十几次）通常说明在拿同一篇
文献反复充当背景，应补检索。校验器会同时报告两个方向：

```bash
node bin/cli.mjs validate --manuscript <正文.md> --lib <library.json> --strict
# missingInList  正文引用了但列表缺失 → 阻断
# unusedInText   列表里有但正文未引用 → 顺序编码制下应为空
```

### 要点 4c：图要"配在论证的位置上"，不是配一张路线图就完事

获批本共 **10 张图**，分布极有规律——**图的密度跟随论证密度**：

| 位置 | 张数 | 作用 |
|---|---|---|
| 1.1 研究意义 | 1 | **现象图**：用一张实测/仿真结果图直观展示问题确实存在 |
| 1.2 研究现状 | 1 | **关系图**：研究目标 ↔ 研究内容 ↔ 关键科学问题的对应关系 |
| 3.1 研究方案 | 8 | **每条研究内容一张技术路线图** + 总体技术路线图 + 网络结构图 |
| 3.2 可行性分析 | 1 | **预研结果图**：证明前期工作已有实际产出，不是空口承诺 |

三条可操作结论：

1. **研究意义处配一张现象图**——比一百字描述更有效，直接让评审"看见"问题。
2. **研究方案处每条研究内容配一张技术路线图**——这是"方案具体、可执行"的最强信号。
3. **可行性分析处配一张预研结果图**（如获批本的"动平台事件成像运动补偿"三栏对比图
   `（a）原始事件帧 （b）补偿事件帧 （c）补偿事件点云`）——把"有基础"从声称变成证据。

> 图一律要有**能独立读懂的图注**（谁、做了什么、看出什么），不要只写"技术路线图"。
> 若用纯 TikZ 生成，见 `pipeline/templates/technical-roadmap.tikz` 与要点 6。

### 要点 5：文献引用格式与编号

正文引用编号顺序即为参考文献编号顺序。建议：

1. 先在（一）中按叙述顺序标记引用
2. 每条参考文献信息必须**可溯源**——优先取自 OpenReview 会议官方 BibTeX 或 arXiv 官方页面
3. 生成参考文献表并做双向校验

```bash
node bin/cli.mjs validate --manuscript runs/<项目名>/deliverables/申请书正文.md \
  --lib runs/<项目名>/work/library.json --min-citations 15
```

> **绝不允许凭记忆填写卷期页码。** 无法核实的标注"待确认"并移出正式列表。
