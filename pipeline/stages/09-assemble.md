# 阶段 9 — 出稿与终检

> **目标**：合并成稿、跑双校验、编译 PDF。
> **前置**：阶段 6、7、8 全部通过
> **产出**：`deliverables/申请书正文.{md,tex,pdf}`、`图1-技术路线图.*`
> **需要网络**：否

## 步骤

### 1. 合并为单一正文

把所有内容写入 **一个** `deliverables/申请书正文.md`，顺序严格为：

```markdown
# <项目题目>

**国家自然科学基金青年科学基金项目（C 类）申请书 · 报告正文**

申请代码：…　|　研究属性：…　|　执行期：…

【成稿说明】（可选，提交前删除）

## （一）立项依据
（为什么要开展此项研究，研究的科学技术价值如何）
### 1.研究背景与意义
### 2.国内外研究现状
## 参考文献
## （二）研究内容
（提纲不做限制，…）
### 1.特色与创新点
#### 1.1.研究特色
#### 1.2.本项目的创新之处
### 2.年度研究计划
### 3.研究工作的自身逻辑与主要内容
## （三）研究基础
### 1.研究基础与可行性分析（…）；
### 2.工作条件（…）；
### 3.正在承担的与本项目相关的科研项目情况（…）；
### 4.完成国家自然科学基金项目情况（…）。
## （四）其他需要说明的情况
### 1.（…）。
### 2.（…）。
### 3.（…）。
### 4.（…）。
### 5.申请人在撰写本申请书时使用生成式人工智能的情况，请详细说明申请书中使用的位置和内容。
### 6.其他（…）。
```

**关键纪律：禁止把各阶段草稿首尾相接。** 必须：
1. 统一人称与时态
2. 消除跨部分重复（尤其是研究价值与创新点）
3. 锁定术语（同一概念全文只用一种表述）
4. 提纲标题与括号文字**逐字**取自 `templates/报告正文-青年C类-2026-提纲.txt`

### 2. 模板合规校验（**必须全通过**）

```bash
node bin/check-template.mjs runs/<项目名>/deliverables/申请书正文.md
```

校验 18 项：四部分标题、括号说明文字、各部分子项、结尾标点、四部分顺序、必含内容（特色与创新点 / 年度研究计划 / 参考文献）。

**未通过则回到对应阶段修复。**

### 3. 引用双向校验（**必须退出码 0**）

```bash
node bin/cli.mjs validate \
  --manuscript runs/<项目名>/deliverables/申请书正文.md \
  --lib runs/<项目名>/work/library.json \
  --min-citations 15 --strict \
  --out runs/<项目名>/work/validate.json
```

| 退出码 | 含义 |
|---|---|
| `0` | 通过 |
| `2` | 发现阻断性问题 |

检出的问题类型：
- `missingInList`：正文引用了但列表缺失
- `unusedInText`：列表列出但正文未引用（挂空文献）
- `numberingIssues`：编号不连续或未从 1 开始
- `formatProblems`：缺年份、缺定位信息（既无卷期页也无 DOI/arXiv/URL）、含未核实占位符
- `duplicateDoi`：重复 DOI

工具兼容**全角方括号 ［1］**与半角 `[1]`，并会自动剥离参考文献区、排除"图1/表2"等非引用方括号。

### 4. 页数与篇幅核对

正文原则上 **≤30 页**（含图表）。

- 超预算时压缩顺序：背景性描述 → 重复表述 → 泛指性价值论证
- **保留不动**：科学问题、结构性缺陷论证、技术路线图、验证方案

### 5. 生成 LaTeX 并编译 PDF

```bash
# 5.1 Markdown → LaTeX
node bin/md2tex.mjs \
  runs/<项目名>/deliverables/申请书正文.md \
  runs/<项目名>/deliverables/申请书正文.tex

# 5.2 XeLaTeX 编译（两遍以生成交叉引用）
#     该脚本会自动找 TeX 二进制、设置国自然通行排版（A4 / 宋体小四 / 1.5 倍行距 / 黑体标题）
& 'bin/compile-tex.ps1'
```

**排版规格**（已内置于 `md2tex.mjs` 的 preamble）：
- A4，页边距 上 2.5 / 下 3.0 / 左 2.5 / 右 2.5 cm
- 正文宋体小四，1.5 倍行距，首行缩进 2 字符
- 标题黑体；正文宋体
- 字体自动回退：系统缺宋体/黑体时用 TeX Live 自带 Fandol 字体
- 页脚居中页码

### 6. LaTeX 质量检查

```bash
node bin/check-tex.mjs runs/<项目名>/deliverables/申请书正文.tex
```

关注：数学公式是否被误转义、表格列宽是否溢出、四部分标题是否存在。

**编译错误必须为 0**；`Overfull \hbox` 若主要来自参考文献长 URL，属可接受（已用 `\sloppy` 缓解）。

### 7. 验证 PDF

```bash
# 页数与渲染验证（Windows 有 Word 时最可靠）
# 或至少确认 PDF 结构与页数
```

判据：`%PDF-` 头 + `%%EOF` 尾、页数 ≤30、四部分标题在页面内容中可检索到。

### 8. 技术路线图

若阶段 7 生成的是占位框：
1. 用 `图1-技术路线图.drawio` 在 https://app.diagrams.net 打开并导出 PNG
2. 命名为 `图1-技术路线图.png` 放到 `.tex` 同目录
3. 重跑 `md2tex.mjs` + `compile-tex.ps1`，图片会自动插入

### 9. 生成式 AI 使用声明核对

确认（四）第 5 项已按实际使用情况撰写，并**转达给用户**：

> 官方要求"详细说明申请书中使用的位置和内容"。**披露不实属科研诚信问题**，请逐条核对是否与实际一致。

## 常见失败模式

| 失败模式 | 表现 | 后果 |
|---|---|---|
| **拼接而非重写** | 各部分术语与表述不一致 | 评审看出"拼凑感" |
| **跳过 validate** | 引用有问题未发现 | 命中央官方负面意见第六条 |
| **模板校验放行** | 提纲标题被改 | 偏离官方要求 |
| **AI 声明含糊** | 未按实际披露 | 科研诚信风险 |
| **页数超标** | 超过 30 页 | 形式风险 |
| **技术路线图缺失** | 只有占位框就交付 | 计算机学科明显失分 |
