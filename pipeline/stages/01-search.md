# 阶段 1 — 检索计划

> **目标**：生成一份**确定性**的检索计划，保证覆盖不因 agent 的主观判断而漂移。
> **前置**：阶段 0 通过
> **产出**：`work/plan.json`
> **需要网络**：否

---

## 为什么用确定性模板

检索覆盖度是科研调研最容易出问题的地方：agent 自由发挥时容易只检索主题词本身，遗漏**综述、失败模式、评测基准、国内工作**这几类关键检索。因此本阶段使用固定模板，保证每条计划都覆盖六类检索：

| 类别 | 目的 | 为什么必需 |
|---|---|---|
| 主题词直查 | 建立基线 | 基础覆盖 |
| 同义词/英文等价 | 跨语种、跨术语覆盖 | 同一概念常有多种表述 |
| **综述检索** | 建立领域地图 | 快速获得主线划分与研究脉络 |
| **失败模式/局限检索** | 定位**结构性不足** | 立项依据的支点；对标官方负面意见第一条 |
| **评测基准检索** | 识别可比基线 | 计算机学科评审的核心关注点 |
| **国内工作检索** | 满足"国内外研究现状" | 官方负面意见第一条：了解现状不全面 |
| venue 定向 | 定位目标会议工作 | 与主题词组合，不单独检索（见下方陷阱） |

## 步骤

### 1. 准备检索参数

| 参数 | 说明 | 示例 |
|---|---|---|
| `--topic` | 中文主题词 | 扩散模型一致性生成 |
| `--english` | 英文等价表达（逗号分隔） | consistency model,few-step sampling |
| `--synonyms` | 同义词扩展 | one-step generation,latent consistency model |
| `--subtopics` | 子方向 | sampling lower bound,depth separation |
| `--venues` | 目标会议/期刊 | NeurIPS,ICML,ICLR,CVPR |
| `--years` | 时间范围 | 2020-2026 |

**`--english` 是必需的。** 计算机学科文献以英文为主，只检索中文主题词会严重漏检。

### 2. 生成计划

```bash
node bin/cli.mjs plan \
  --topic "<中文主题>" \
  --english "<英文1>,<英文2>" \
  --synonyms "<同义词>" \
  --subtopics "<子方向1>,<子方向2>" \
  --venues "<venue1>,<venue2>" \
  --years 2020-2026 \
  --out runs/<项目名>/work/plan.json
```

命令会自动自检并告警（`plan.json.audit`）。

### 3. 人工审阅并补充

读取 `plan.json`，检查：

1. 六类检索是否齐全（看 `purpose` 字段）
2. 英文表达是否覆盖主要术语变体
3. 子方向是否与研究内容对应
4. **是否存在明显漏检风险**——若有，手动追加到 `plan.json`

追加格式：

```json
{ "query": "<检索式>", "purpose": "<为什么需要>", "manual": true }
```

### 4. 确定数据源顺序

默认无需指定：`search --fallback` 会按 `crossref → arxiv → openreview → openalex → s2 → europepmc` 自动尝试并择优。

## 完成判据

### 硬判据

- **H1**：`work/plan.json` 存在且合法
- **H2**：计划条数 ≥ 12
- **H3**：六类检索齐备（主题 / 综述 / 不足 / 基准 / 国内）
- **H4**：存在英文检索式
- **H5**：`plan.json.audit.ok === true`（无单独 venue 检索式、无缺失类别、无重复）

### 软判据

- **S1**：已列出目标 venue 的定向检索
- **S2**：人工追加的检索式已标注 `manual: true` 与理由
- **S3**：子方向数量 ≥ 3

### 评级

- **优**：H1–H5 + S1–S3
- **良**：H1–H5 + S1–S2
- **中**：H1–H5
- **差**：任一 H 不满足

---

## 陷阱

| 陷阱 | 说明 |
|---|---|
| **单独检索 venue 名** | `NeurIPS` 这样的单 token 检索式会返回大量无关结果。模板已改为「主题词 + venue」组合，`audit` 会检出残留 |
| **只检索中文主题词** | 计算机学科会漏掉绝大部分文献 |
| **检索式过于宽泛** | 如只检索 `safety`。应加上方法名、任务名限定 |
| **综述检索返回 0 条也放过** | 综述是建立领域地图的关键，返回 0 必须改写重试 |
