## 官方提纲（**必须逐字保留**）

```
（二）研究内容
（提纲不做限制，请按照研究工作的自身逻辑撰写。应提炼出特色与创新点、年度研究计划）
```

**关键理解**：官方明示"提纲不做限制"，但**必须提炼出两样东西**：

1. **特色与创新点**（官方示例层级：`1.特色与创新点` → `1.1.研究特色` / `1.2.本项目的创新之处`）
2. **年度研究计划**（`2.年度研究计划`）

因此推荐结构：把这两项作为 `1.` 和 `2.` 直接列出，再把研究内容主体放入 `3.`。这样既满足官方"必须含"的要求，又符合"按自身逻辑撰写"。

## 执行要点

### 要点 1：用「假说验证链」组织研究内容

**推荐结构**：
```
科学假说
  ├─ 研究内容1：验证假说的某个前提条件
  ├─ 研究内容2：构造并检验假说预测的机制
  ├─ 研究内容3：在另一设定下检验假说的一般性
  └─ 研究内容4：假说成立后的方法与系统实现
```

**删除检验**：删掉任何一项研究内容，假说是否仍能被完整检验？若答案是"仍能"，该项即为冗余工作包，应删除或合并。

**避免**机械按生命周期切分（如"训练→推理→部署"），除非科学问题确实沿该生命周期分布。

**面上项目额外要求：必须有「统一抽象」把研究内容锁成整体**（青年可略）。
面上项目范围大，四条研究内容若读起来是"四个不相干的课题"，是最常见的被否原因。
做法是找到一个贯穿全部内容的概念，让每条内容成为**同一抽象在不同层面的展开**。

实测案例（面上·高铁接触网缺陷检测）用「**关系**」作为统一抽象：

| 研究内容 | 在统一抽象下的角色 |
|---|---|
| 场景结构化特性知识分析与建模 | **建立**构型关系、拓扑关系、依附关系 |
| 关键部件定位方法 | **用**构型关系 + 拓扑关系约束定位 |
| 细微缺陷检测方法 | **用**依附关系推理 + 注意力机制协同 |
| 定位-识别一体化架构 | 解决时效性，令四条共享特征 |

四条内容因此不是并列任务，而是"建立关系 → 用关系定位 → 用关系识别 → 共享关系特征"。

**自检方法**：用一句话写出这条抽象（如"本项目研究 X 的四类关系及其推理机制"）。
若写不出，或写出来之后某条研究内容不在该抽象内，说明内容划分有问题，需重划。
把这条抽象**画进总体技术路线图**（作为图的顶层节点），与科学问题并列。

### 要点 2：必须有核心科学洞察

在展开方法之前，先用一段话回答"**这个方法为什么能 work**"：

```
[观察] 我们在 [什么条件] 下观察到 [什么具体现象]。
[解释] 该现象提示 [什么机理]。
[推论] 若该机理成立，则 [什么设计] 应当能 [解决什么问题]。
```

**若写不出这段**，说明方法只是组件拼装。

### 要点 3：必须有技术路线图（而且要**按研究内容分张**）

计算机学科评审最关注的可视化内容。四要素缺一不可：

| 要素 | 要求 |
|---|---|
| 科学问题入口 | 图的最上方写出要回答的科学问题 |
| 研究内容分块 | 3-4 项研究内容作为模块 |
| 模块间关系 | 箭头表示数据流/依赖（不能只有并列方块） |
| 可检验产出 | 每个模块的产出与验证方式 |

**图的密度要跟论证密度走。** 参考获批本的分布：研究方案节共 **8 张图**——
一张总体技术路线图，**外加每条研究内容各一张技术路线图**，再加网络结构示意图。
只画一张总图就交差，等于把"方案具体、可执行"这个最强信号丢掉了。

建议的出图清单：

| 图 | 位置 | 内容 |
|---|---|---|
| 图 A | 3.1 总体思路 | 总体技术路线：科学问题 → 研究内容 → 方法 → 验证 → 产出 |
| 图 B–D | 各条研究内容下 | **每条研究内容一张技术路线图**：输入 → 关键处理 → 中间表征 → 输出 |
| 图 E | 核心方法处 | 网络结构/算法流程示意图（含模块名与张量流向） |
| 图 F | 验证方案处 | 实验设计图或数据流图 |

**出图方式**（按推荐顺序）：

- **方式 A（首选，纯 TikZ）**：复制 `pipeline/templates/technical-roadmap.tikz` 到正文
  `.tex` 同目录，改名为 `图1-技术路线图.tikz`，正文里照常写
  `![图1 技术路线图](图1-技术路线图.png)` 即自动优先嵌入。
  优点：矢量（打印不失真）、**不需要 drawio/Visio**、单一 `.tex` 源文件即可复现整份稿件、
  纯文本可版本管理。多张图时复制多份并改名为 `图2-*.tikz`、`图3-*.tikz`。
- **方式 B（draw.io / Mermaid → PNG）**：用 `pipeline/templates/roadmap-templates.md` 的模板出图，
  导出 PNG 放在与 `.tex` 同目录。**若图片缺失，LaTeX 会自动回退为占位框，不会编译失败**——
  正因如此，**必须**用 `bin/pdf-probe.mjs --expect-figure` 确认图真的嵌进去了（见阶段 9）。
- **方式 C（最次）**：文字版 ASCII 框图，仅作临时占位。

> **图注必须能独立读懂**：写清"谁、做了什么、看出什么"，而不是只写"技术路线图"。
> 获批本的正例：`图10 动平台事件成像运动补偿` 配三栏对比 `（a）原始事件帧
> （b）补偿事件帧 （c）补偿事件点云`——图注 + 分栏标签本身就把结论说完了。

### 要点 3b：验证方案必须成节，**不得只散落在各研究内容里**

**实测教训（重要）**：一份**已获批**的面上项目申请书，3.1 研究方案写了 9,351 字、
11 张图，却**通篇没有独立的实验验证方案**——无数据集划分、无评价指标、无基线、无消融。
它在 2021 版模板下仍然获批，但：

> **在 2026 版下这是硬伤。** 2026 版（二）的括号说明明确要求"按照研究工作的自身逻辑撰写"，
> 且约束从"建议 8000 字"改为"**不超过 30 页（含图表）**"——官方实质给了把方案写厚的空间，
> 也就没有省略验证方案的理由。照搬该本子的这一点，等于在 30 页里留一个空白格。

因此研究方案中**必须有一节专门写验证**（通常放在核心方法之后、预期成果之前），
且以下九项**逐项可见**：

| 项 | 要求 |
|---|---|
| 数据集/基准 | 具体名称、规模、**选择理由**（为什么这批数据能检验你的假说） |
| 基线 | 3–5 个，**必须包含该方向最强竞争者**，不能只挑弱基线 |
| 评价指标 | 名称、定义、为何该指标能反映有效性 |
| 对比公平性 | 相同数据划分、相同算力预算、相同调参预算 |
| **消融** | **每项声称的创新组件都要有对应消融** |
| **假说否定条件** | 什么结果会否定你的科学假说（与（一）的科学问题呼应） |
| 统计显著性 | 多随机种子、均值与方差/置信区间 |
| 算力与成本 | 具体卡时/机型，与（三）2 的工作条件一致 |
| 可复现性 | 开源计划、超参、随机种子 |

**自检**：把研究方案通读一遍，问"如果评审问『你怎么证明它 work』，正文哪一节回答"。
若答案是"分散在各处、需要自己拼"，说明验证节缺位。

> **建议**：主动报告至少一项适用边界或不利结果，比全篇报喜更能赢得评审信任。

### 要点 4：必须有验证方案

计算机学科评审判断"方法可行性"的主要依据就是验证设计。**缺验证方案直接判 `gate = fail`。**

必备内容：
- [ ] 数据集/基准：具体名称、规模、选择理由
- [ ] **基线：必须包含该方向最强竞争者**（3-5 个）
- [ ] 评价指标：名称、定义、为何能反映有效性
- [ ] 对比公平性：相同数据划分、相同算力预算、相同调参预算
- [ ] **消融：每项声称的创新组件都要有对应消融**
- [ ] **假说否定条件**：什么结果会否定科学假说
- [ ] 统计显著性：多次随机种子、均值与方差/置信区间
- [ ] 算力与成本
- [ ] 可复现性：开源计划、超参、随机种子

**建议**：主动报告至少一项适用边界或不利结果，比全篇报喜更能赢得评审信任。

### 要点 5：创新点与年度计划的硬约束

- **创新点 2-3 个**，彼此不重叠；每个在方法部分有对应技术方案、在研究内容中有对应条目
- **"首次"慎用**：确实属于首次提出的才能用
- **年度计划年数必须与执行期限一致**，不得套用三年模板
- 每年要有**可考核的里程碑产出**

**创新点的标准写法（照获批本的模板）**：每条用一个"针对X，提出Y"的小标题，
后接一段"**现有方法做不到 Z → 本课题如何做到**"。关键是**先立靶子再开枪**——
没有对照的"创新"读起来只是工作描述。

参考获批本原文（三条创新点，结构完全一致）：

> **（2）针对事件点云局部结构感知，提出基于知识数据联合驱动的几何感知模型。**
> **现有的**几何感知方法或针对二维几何结构，或在潜空间中通过数据拟合实现几何感知，
> **缺乏**对三维几何结构的显式建模与特征表达。**本课题**针对事件点云的典型几何结构……
> 通过高阶参数空间几何表达数学模型对三维几何结构的显式建模，并将其融入到特征提取网络中……

拆出它的四段式：**① 我提出什么 → ② 现有方法的具体不足（指名到方法类别，不空泛）
→ ③ 我怎么做 → ④ 因此获得什么能力**。

另注意获批本把「特色」与「创新」分开写：
**特色 = 研究思路层面的不同**（为什么整体上是另一条路），
**创新 = 具体技术贡献**（提出了什么新方法/新模型）。两者不可混为一谈，也不可只写其一。

### 要点 6：预期研究成果的量级约束

官方负面意见第五条明确列出：

> 预期研究成果过高、过多，超出了申请人以往研究基础和项目组以往研究工作所表现的能力

且有应用背景的项目还要评议"潜在应用价值"。因此成果数量应**与申请人近三年实际发表记录处于同一量级**。若用户未提供发表记录，**不要填具体数字**，写成带核实提示的建议量级。

## 完成判据

### 硬判据

- **H1**：关键科学问题 1-2 个，与（一）的假说严格对应
- **H2**：通过 science/technology 形态自检，否定条件已写出
- **H3**：研究内容通过**删除检验**（无冗余工作包）
- **H4**：提纲标题与括号文字逐字保留；含"特色与创新点"（1.1/1.2）与"年度研究计划"
- **H5**：**存在核心科学洞察的独立表述**（观察→解释→推论）
- **H6**：**存在技术路线图**（图片或文字版），四要素齐全
- **H7**：**存在完整验证方案**，含最强基线、完整消融、假说否定条件
- **H8**：未把"系统研究""全面总结""集成研究"作为研究特色
- **H9**：创新点 2-3 个且不重叠，每个都有对应技术方案
- **H10**：预期成果量级与团队能力匹配（或已标注核实提示）
- **H11**：年度计划年数与执行期限一致

### 软判据

- **S1**：研究内容 3-4 项，彼此有递进关系
- **S2**：每项研究内容都有可检验的中间产出
- **S3**：技术路线图模块名与正文标题一致
- **S4**：报告了至少一项适用边界或不利结果
- **S5**：说明了算力需求与可获得性
- **S6**：本部分占正文 50% 以上

### 评级

按官方综合评价标准自评。**特别提示**：官方对青年基金的评议要求包含"申请人的创新潜力"一项。
