## 执行要点

### （三）1.研究基础与可行性分析

拆成两块：

**1.1 与本项目相关的研究工作积累和已取得的研究工作成绩**
- 研究方向的延续性（与本项目在对象上连续、在层次上递进）
- 已取得的成果表格（题目/发表情况/本人排名/核心结论/对应研究内容）
- **前期预研结果与初步实验发现**（自由探索类的竞争力核心）
- 技术储备对照表（每项研究内容所需能力 ↔ 申请人的对应储备）

**1.2 可行性分析**

必须**逐条对应（二）中列出的关键科学问题**来论证，一条科学问题配一段证据。
这样评审才能确认"每个承诺都有底气"，而不是读一堆通用理由。

获批本的做法（原文）：

> **异步事件流数据表征**：前期研究中，申请人对点云数据的结构组成、数据去噪、空间滤波、
> 空间聚类等工作进行了充分的研究……构建了事件流时空点云。……图10展示了运动补偿和事件
> 点云的可视化结果，可以看出经过运动补偿后事件数量显著减少，目标和背景的几何结构更加清晰。
>
> **知识数据联合驱动几何感知模型**：……申请人前期围绕点云数据的结构特性，设计了专用的
> 距离注意力模块……相关成果已发表在国际期刊上（**2023 PR，代表性论著 2**）。……
> 相关成果发表在国际期刊上（**2023 TNNLS，代表性论著 3**）。

拆出它的三段式（每条科学问题都这么写）：

```
① 前期已做了什么（具体到方法与对象，不写"有一定研究"）
② 得到了什么可展示的结果（引预研图 / 引已发表论著编号）
③ 本项目将在此基础上推进到什么（明确增量在哪，不是重复前期工作）
```

四条硬性要求：

| 要求 | 说明 |
|---|---|
| **有编号可查** | 已发表成果写成「（2023 PR，代表性论著 2）」，与（三）1 的成果目录对得上 |
| **有图给图** | 预研结果配图（见下方"预研结果图"） |
| **增量明确** | 说清"本项目将在此基础上进一步发展……"，让评审看到不是把已发表工作再报一遍 |
| **风险预案** | 至少 4-6 项风险，逐项给出预案 |

**预研结果图**：获批本在可行性分析处配了 `图10 动平台事件成像运动补偿`，三栏对比
`（a）原始事件帧 （b）补偿事件帧 （c）补偿事件点云`，图注一句话给出结论。
这一张图把"有基础"从**声称**变成了**证据**，是可行性分析里性价比最高的内容。

> **不可代写。** 上述所有① ② 内容只能来自申请人本人提供的成果清单与预研数据。
> 若申请人未提供，**留出结构化空位并明确标注**，绝不虚构论文、编号或实验结论。

#### 面上项目：可行性必须给出三类可核验的硬证据

面上项目的可行性分析篇幅实测约为青年的 1.5 倍，且证据密度显著更高。
必须逐类追问申请人，凑齐以下三类（**每一类都要带编号或数字**）：

| 证据类别 | 实测样本的具体形式 | 追问要点 |
|---|---|---|
| **① 平台与产业合作** | "已与**武汉铁路局、广州铁路局**等应用单位建立深度合作关系，包括去控制室学习现行缺陷检测流程、去图像采集现场和人工判读现场学习相关缺陷判读知识" | 合作单位全称、合作形式、能否出具证明 |
| **② 数据与知识产权** | "已收集**千万张**图像，人工标注**约一万张**"；发明专利 2 项（公开号 **CN110321944A**、**CN110428398A**）；软件著作权 **2019SR0351908** | 数据规模与标注量、专利/软著编号（**必须可查**） |
| **③ 实机测试的对比数字** | "软件系统……**两天内**检测完了大约 **2 万张**吊弦图像和绝缘子图像，并成功检出所有缺陷部件；若由目检人员人工判读，**大概需要一周左右**" | 有无现场测试、与人工/基线的量化对比 |

**③ 是面上最有说服力的一类**——它把"技术可行"变成了"已经跑过、并且比现有人工方式快 N 倍"。
若申请人确实没有实机测试数据，**如实写明"尚未开展现场测试"并给出测试计划**，
不得编造数字或测试结论。

> **注意**：专利公开号、软著登记号、数据集规模**都是可被评审核验的**。
> 编造这类信息不只是学术不端，而且极易被查证。缺失就留空。

#### 逐条论证的"共性 + 差异"四步（面上尤其需要）

每条关键科学问题的可行性，都要先证明**方法上有可借鉴的共性**（说明不是空想），
再指出**本场景的差异**（说明不是照搬），最后才说本项目要做的新工作。
实测获批本的原文：

> 针对场景结构化特性知识分析方面，**究其原理，本质上是解决拓扑结构化和关系结构建模的问题，
> 与人体的标志点结构化建模存在方法层面的共性**。申请人在人体标志点结构化建模有良好的基础，
> 在代表作 2 中提出基于特征点的构型结构化建模……**然而高铁接触网场景结构和人体结构仍存在
> 差异性**，则本研究进一步将高铁场景中部件之间的构型关系进行建模……

抽象成四步：

```text
① 共性：这个问题的本质是什么？哪个成熟领域已有方法？（"本质上是解决 X 问题"）
② 申请人已有基础：在该领域做过什么（挂代表作编号，如"在代表作 2 中提出……"）
③ 差异：本场景与那个成熟领域有何不同（证明不是照搬）
④ 因此：本项目要做的新工作（明确的增量）
```

**为什么面上更需要这个结构**：面上的评审要点是"申请人是否真的理解这个领域"。
直接说"我要研究 X"无法体现理解；而"X 的本质是 Y，我在 Y 上有基础，但 X 与 Y 有
Z 的差异，所以要发展 W"——这一串本身就证明了理解深度。

**这类论证只能由申请人提供**：①②必须来自申请人的真实成果与判断。
若申请人说不出"共性在哪、差异在哪"，说明科学问题尚未想透，应回到阶段 5 重做，
**不得由 agent 代为编造这层理解**。

> **可行性分析的位置**：按官方提纲，它属于**（三）1**，**不是**（二）的一部分。这是最常见的错位。

3. **尚缺少的实验条件与拟解决的途径** ← **官方明确要求，不可省略**
4. 研究基地利用计划与落实情况（不涉及填"无"）

### （三）3.正在承担的与本项目相关的科研项目情况

按官方字段逐项填写表格：资助机构 / 项目类别 / 批准号 / 项目名称 / 获资助金额 / 起止年月 / 本人负责的内容 / 与本项目的关系及区别。无则填"无"。

#### （四）5 的写法（**官方必填，不得含糊**）

官方要求"**详细说明申请书中使用的位置和内容**"。建议分四段：

1. **文献检索与元数据核验**：使用了什么工具、检索了哪些数据库、参考文献元数据来自何处、如何核验
2. **研究现状梳理**：用 AI 做了哪些归纳、论断是否可溯源到文献编号
3. **文字起草与格式检查**：起草了哪些部分、执行了哪些自动检查
4. **未使用生成式人工智能的部分**：**明确列出**由申请人本人完成的内容（科学问题凝练、研究假说、研究内容划分、创新点与研究方案设计等），以及由申请人据实填写的事实性内容

最后附一行提示：请申请人逐条核对与实际使用情况是否一致；**披露不实属科研诚信问题**。
